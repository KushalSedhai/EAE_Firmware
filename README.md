EAE Firmware

This project is a simple firmware simulation for the EAE Electrical and Controls Challenge.

The purpose of the project is to demonstrate basic firmware concepts used in a cooling control system, including:

CAN bus message simulation

PID control

State-machine logic

Command-line setpoint input

CMake build configuration

Shell-script execution using MSYS2

Unit testing using GoogleTest

The main firmware is written in C. GoogleTest requires C++, so the unit-test file is written in C++ and calls the C firmware functions using extern "C".

System Overview

The simulated cooling system uses the following inputs:

Ignition state

Coolant temperature

Coolant level

CAN communication status

The controller produces the following outputs:

Pump command from 0 to 100%

Fan command from 0 to 100%

System state

Fault status

The basic control flow is:

Simulated Sensor Data
        |
        v
    CAN Message
        |
        v
   Fault Manager
        |
        v
   State Machine
        |
        v
  Cooling Control
        |
        +----> Pump Command
        |
        +----> PID ----> Fan Command
        |
        v
   CAN Command Message

System States

The firmware uses four operating states:

STATE_OFF

STATE_NORMAL

STATE_WARNING

STATE_FAULT

The state is selected using simple operating conditions.

Ignition OFF
    -> STATE_OFF

Fault detected
    -> STATE_FAULT

Temperature above 80 C
    -> STATE_WARNING

Otherwise
    -> STATE_NORMAL

Fault Handling

The following faults are simulated:

Low coolant level

Invalid temperature sensor reading

CAN communication failure

The valid simulated temperature range is:

-40 C to 150 C

A temperature outside this range is treated as a sensor fault.

Pump and Fan Control

Normal State

In normal operation:

Pump = 60%
Fan  = PID controlled

Warning State

If coolant temperature rises above 80 C:

Pump = 100%
Fan  = PID controlled

Off or Fault State

Pump = 0%
Fan  = 0%

PID Controller

The fan speed is calculated using a simple PID controller.

The default temperature setpoint is:

65 C

The initial PID gains used for the simulation are:

Kp = 5.0
Ki = 0.1
Kd = 0.5

The PID output is limited to:

0% to 100%

The purpose of the PID controller is to increase fan demand as coolant temperature rises above the requested setpoint.

CAN Simulation

Two CAN message IDs are used.

Sensor Data

CAN ID: 0x100

Message contents:

Byte 0-1 : Coolant temperature
Byte 2   : Ignition state
Byte 3   : Coolant level

Temperature is transmitted in 0.1 C units.

For example:

72.5 C -> 725

Cooling Command

CAN ID: 0x200

Message contents:

Byte 0 : Pump command
Byte 1 : Fan command
Byte 2 : System state
Byte 3 : Fault code

Build Requirements

The project was developed using:

GCC

CMake

Ninja

MSYS2 UCRT64

GoogleTest

GoogleTest is downloaded and managed automatically by CMake using FetchContent. The dependency is not stored directly in the repository.

Build with CMake

From the project directory in the MSYS2 UCRT64 terminal:

cmake -S . -B build -G Ninja
cmake --build build

The firmware executable will be created inside the build directory.

Run the Firmware

Run using the default 65 C setpoint:

./build/eae_firmware.exe

A different setpoint can be passed using the --setpoint command-line argument.

Example:

./build/eae_firmware.exe --setpoint 75

This runs the simulation using:

Setpoint = 75 C

Run Using the Shell Script

The provided shell script builds and launches the firmware.

Make the script executable if required:

chmod +x run.sh

Run with the default setpoint:

./run.sh

Run with a different setpoint:

./run.sh 75

The script builds the project and passes the selected value to the firmware as:

--setpoint 75

Unit Testing

GoogleTest is used to test basic firmware behavior.

The current tests check:

Ignition OFF causes STATE_OFF

Healthy operating conditions cause STATE_NORMAL

Low coolant produces FAULT_LOW_COOLANT

PID output does not exceed 100%

Build the project first:

cmake --build build

Then run the tests:

ctest --test-dir build --output-on-failure

Expected result:

100% tests passed

Notes

This project is intentionally kept simple and readable. It is a software simulation and does not communicate with physical CAN hardware, sensors, pumps, or fans.

The goal is to demonstrate the requested firmware concepts while keeping the implementation understandable and appropriate for a junior-level firmware project.
